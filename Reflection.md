In this assignment, I learned how applications communicate via SOAP based messages using XML, but via my client. I created a calculator web service and connected to a public SOAP Calculator service with a client I built in Python using the Zeep library. The application includes addition, subtraction, multiplication, and division operations, and I implemented some validation to ensure the user provides supported operations and inputs valid numbers. The calculator has Flask GET and POST endpoints.

A key difficulty for me was in trying to reach the service, even though I could get to the service webpage. The SOAP call caused my application to throw a SOAP service error. That error provided me a valuable lesson. It helped me realize that being able to get to the service webpage, even with the service description (the WSDL), doesn't always guarantee that the SOAP operations will function as intended. Also, Zeep was a huge time saver because I did not need to write and XML manually. 

For the most part, SOAP services aren't as prevalent as REST based services in today's day and age. However, SOAP services are still very relevant, especially in large enterprise environments. For this reason, I'm definitely interested in continuing my exploration and learning more about service contracts and systems integration. I would love to get a deeper understanding of how to troubleshoot SOAP based services.
